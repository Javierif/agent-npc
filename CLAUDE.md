# CLAUDE.md

Project guide for Claude Code. For a short overview see [README.md](README.md); the detailed user documentation lives in `docs/` (`features.md`, `obsidian.md`, `cerebro.md`, `integrations.md` (Telegram, Slack/Feishu, bridges, quota, mobile view, WSL/SSH), `themes.md`, `security.md`, `testing.md` (tests and what has been verified)); for the MVP scope, [MVP.md](MVP.md). `site/` is the static landing page (`npm run site`, `npm run site:build`, deployed by `.github/workflows/pages.yml`); `site/hero-gif.ts` + `site/receive-gif.mjs` (and `characters-png.ts`) regenerate `docs/media/hero.gif` and `characters.png` from the real sprites.

## What it is

**claude-npc** is a desktop NPC for Claude Code. A small original character (*Postie*, a peach-colored blob with a post-it note as a hat) walks along the top of the taskbar, reacts to what Claude does, asks you for permissions and **lets you send it tasks**, including the ones you write in your Obsidian notes. Optionally, your vault serves as its memory (off by default), you can ask it questions with citations, it can reflect when each session closes (lessons, decisions and to-dos; also off) and, if you enable it, forge a personality from what it learns about how you work (`Claude NPC/Personalidad.md`; also off). Over time it forgets what it doesn't use (archives it, without deleting; `brainForget`, off), consolidates what it learned into principles and habits once a week ("dreaming") and joins together the notes it remembers together. There are three alternative characters selectable in the themes: *Don Rana* (Mr. Frog), *Don Pato* (Mr. Duck) and *Don Hámster* (Mr. Hamster).

- Status: **MVP** (v0.1.0). Tested on Windows 11; macOS and Linux are written but neither compiled nor tested.
- Stack: **Tauri 2** (Rust, 2024 edition) + **framework-free TypeScript** frontend + **Vite**. Transparent, always-on-top overlay window with no taskbar entry, click-through except over the character and its panels.
- Project language: documentation, code comments and Rust doc-comments are in **English**. UI strings are keyed by their Spanish text in `DICT` (`src/i18n.ts`) and shown in 5 interface languages (es/en/pt/fr/de); any new visible string must still go through `t()` with `e(en, pt, fr, de)`.
- MIT license. Third-party attributions are in `NOTICE`. The character is original: do not copy code or art from other projects, and respect the license of any code you adapt.

## Philosophy

1. **Local first, no services of our own.** Everything runs on the user's machine. The NPC uses the user's own `claude` CLI (`claude -p`), their session and their subscription. There is no backend, telemetry or accounts.
2. **No plugins or dependencies on the other tools.** Claude Code connects through *HTTP hooks* in `~/.claude/settings.json`; Obsidian is handled over the vault's Markdown files and, for quick actions, with `obsidian://` URIs and the official CLI (no plugin); other agents come in through a generic HTTP endpoint.
3. **Graceful degradation.** If the NPC is not open, the bridges don't get in the way (neutral response) and the agent carries on as usual. Without hooks, the NPC is still useful for launching tasks.
4. **Secure by default.** Tasks launched from the NPC are read-only (`Read`, `Glob`, `Grep`, `LS`) unless *Permitir que Claude edite archivos* (Allow Claude to edit files) is turned on. Auto-approval is off by default. Servers listen only on `127.0.0.1` (the mobile view is opt-in, `GET` only and token-protected). Webhook and theme URLs must be `https`.
5. **Don't touch what isn't yours without a safety net.** Hooks are added while preserving the user's own and keeping a backup (`settings.json.claude-npc.bak`); they are identified by the `src=claude-npc` marker so they can be removed cleanly. When writing to an Obsidian note, if it changed while Claude was working, the task is relocated by its text and, if it is no longer there, **nothing is written**.
6. **Honesty about what was tested.** The README status note and [docs/testing.md](docs/testing.md) distinguish what was verified in the real app from what was not. Keep that distinction: do not mark as verified something that was only tested against simulations.
7. **Original and contained.** The character is drawn from code (one base, all poses derived). The MVP has a closed scope (see `MVP.md`): what is left out was decided, not forgotten.

## Install and commands

Requirements: **Node 20+**, **Rust** (recent stable toolchain, 2024 edition), **WebView2** (Windows) and `claude` on the `PATH` with a signed-in session. The NPC checks that session with `claude auth status` and, if it is missing, offers *Iniciar sesión* (Sign in) (opens a terminal with `claude auth login`).

```bash
npm install
npm run tauri dev      # full app (starts Vite on :1420 and the Tauri window)
npm run build          # tsc + vite build (frontend to dist/)
npm run tauri build    # packaging
npm run bridge         # builds npc-bridge -> src-tauri/target/debug/npc-bridge
```

Tests:

```bash
npm run test:ui        # node --test tests/*.test.mjs  (translations complete and consistent in the 5 languages; Markdown interpreter in `markdown.ts`)
npm run test           # cargo test: hooks, permissions, background sessions, vault, Obsidian actions (URIs, command parser), vault memory (index, recall with per-project relevance, capture and session log, reflection, personality, forgetting and reinforcement, associations, dreaming, questions with citations, weekly summary, maintenance, task notes, panel; the hidden internal sessions have no tests of their own), suggestions for your notes (links and tags, apply), Telegram/webhooks (simulated servers), bridges, mobile view, themes, history, claude parser
npx tsc --noEmit       # frontend types
```

Preview the UI without Tauri: `npx vite` and open `http://localhost:1420/tests/preview.html` (simulated backend with `mockIPC` in `tests/mock.ts`). When you add a Tauri command that the UI uses, also add its case to `tests/mock.ts`.

After installing, the user presses **Conectar con Claude Code** (Connect with Claude Code) (Sessions or Settings) to install the hooks and restarts their open sessions. The quota (5 h / 7 d / context rings) additionally requires a `statusLine` that does a `curl` to `/usage` (see [docs/integrations.md](docs/integrations.md)).

## Architecture

```
Claude Code ──HTTP hooks──▶ 127.0.0.1:47650 (hooks.rs) ──Tauri events──▶ frontend (main.ts → npc.ts / ui.ts)
Other agents ──npc-bridge──▶ /agent                                              │
statusLine ──curl──▶ /usage                                         invoke() ◀────┘ (api.ts)
frontend ──start_task──▶ runner.rs ──spawn──▶ `claude -p` (stream-json) ──▶ progress/result
vault.rs ◀── watches the vault's *.md (`- [ ] … #claude`) ──▶ runner ──▶ rewrites the note
```

When resuming a session (`resume`), it registers it as `headless` for the duration of the process and frees it when finished. With memory active, `brain::task_result` writes the response as a note in `Claude NPC/Tareas/` and the task's quote ends in `→ [[note]]`. `claude_command` is `pub(crate)` and is reused by `brain/reflect.rs`. |
| `vault.rs` | Obsidian: detects vaults, scans `#claude` tasks, watches changes, `Claude NPC Inbox.md` inbox, safe rewriting of the note. It also exports `civil_date`/`civil_hm` (UTC), `collect_markdown`, `MAX_FILE_BYTES` and `write_atomic`, used by `brain/`, and `today_days`/`date_from_days`/`days_from_date` (days since 1970 in UTC). `task_context` interprets `[[ ]]` and `📁` in a task (see `runner.rs`). |
| `brain/` (`mod.rs`, `index.rs`, `recall.rs`, `capture.rs`, `suggest.rs`, `reflect.rs`, `persona.rs`, `ask.rs`, `review.rs`, `strength.rs`, `dream.rs`, `associations.rs`) | The vault as the NPC's memory; opt-in (`brainEnabled`, off by default). `index.rs`: in-memory index of the vault's notes (titles, aliases, `#tags`, `[[wikilinks]]` with backlinks and weighted terms for BM25; no embeddings; `Index.assoc` with the associations from `associations.rs`; `importance` from the frontmatter, 1–5 and 3 by default; folder weights: `Archivo/` 0, `Hábitos/` 1.3, `Memoria/` 1.2, `Sesiones/` 0.7); it skips folders in `brainExclude`, notes with `claude: false` and files larger than `MAX_FILE_BYTES`; 60 s cache rebuilt in the background (`warm` at startup). `recall.rs`: BM25 with expansion through links and associations up to two hops (`via`), weaker at each hop; `strength::factor` multiplies the score of the NPC's memories; memories are reinforced when used, and the "Memoria del usuario (Obsidian)" block (`BRIEF_HEADER`, max. 5 notes and 2,000 characters; `strip_brief` removes it); `is_wrapped` also recognizes the personality header (`PERSONA_HEADER`). `recall_in(index, query, k, project)`: ×1.4 (`PROJECT_BOOST`) for the `Proyecto - <folder>` note and the notes that link to it; on equal score, the order is that of the notes (deterministic). `capture.rs`: on `Stop`/`SessionEnd` it writes or refreshes `Claude NPC/Sesiones/<date> <topic> (<id8>).md`, which is a session log (`## Bitácora`: one line per turn, `HH:MM · what was asked → start of the answer`, max. 60; a second `Stop` for the same prompt refreshes its last line) and, after a reflection, carries `## Resumen` at the top (`set_session_summary`; both sections are preserved on refresh); it links `Claude NPC/Proyectos/Proyecto - <folder>.md` and `Claude NPC/Diario/<date>.md`; it only refreshes notes carrying the `<!-- claude-npc:auto -->` marker (if the user deletes it, it is left alone); `brain_remember` stores facts in `Claude NPC/Memoria/` (`importance: 4`). `task_note` writes the answer to a vault task as `Claude NPC/Tareas/<date> <task>.md` (auto marker, `**Origen:** [[note]]`, "Relacionado" only with existing notes, the text without `#claude`; the queries require the Dataview plugin. Writing is confined to `Claude NPC/` with sanitized names; the user's notes are not edited (except the exception in `suggest.rs`). `suggest.rs`: proposals for the user's notes, of two kinds: `link` (wrap in a `[[wikilink]]` the first unlinked mention of another note's title; ignores code, existing links, URLs, headings and notes in `Claude NPC/`; only unique titles of ≥4 letters; max. 3 per note, over the 400 most recent notes) and `tag` (add a frequent tag, used in ≥3 notes, to notes with no tags, in the frontmatter). `suggest` only reads. `apply` runs only when *Aplicar* (Apply) is pressed: it rereads the note and writes only if the proposed line is still identical (otherwise, error and nothing is written); it validates that the path is inside the vault, `.md`, outside `Claude NPC/`, and that `after` differs from `before` only by adding `[[ ]]`; it preserves CRLF and writes atomically. It does not depend on `brainEnabled`. `reflect.rs`: session reflection (opt-in with `brainReflect`, off by default; requires `brainEnabled`). On `SessionEnd` (`on_session` with `ended`) or with *Reflexionar ahora* (Reflect now) (`brain_reflect`, on the most recent session that is not a reflection), if the working folder is not in `brainExclude`, it reads the end of the transcript (`history::conversation_excerpt`: only user and Claude text, max. 12,000 characters; minimum 2 user turns and 400 characters) and launches `claude -p --model haiku --output-format text --allowedTools Read,Glob,Grep,LS` with cwd in the vault (150 s timeout). The prompt starts with `MARKER` (`[claude-npc:reflexion]`): `on_session` and `hook_context` ignore those sessions to avoid looping (`is_internal`), and `hooks.rs` and `history.rs` hide them from Sessions and Recent (not verified with a real `claude`). `exclusive(work)` is the lock for a single model execution, shared with the question, the weekly summary and dreaming; `run_model(prompt, vault, model)` accepts an optional model (`None` = the user's). It expects a JSON (`summary`, `lessons`, `decisions`, `todos` and, with `brainPersona`, `persona`; each lesson and decision carries `importance`, 1–5 and 3 by default) that is validated and written under `Claude NPC/` (the `summary` goes to `## Resumen` of the session note; a lesson repeated in another session reinforces its note with `strength::reinforce`): `Memoria/` (lessons and decisions, max. 4 and 3; if an NPC note already exists, it appends a dated line; if the user removed the marker, it leaves it alone), `Pendientes.md` (`- [ ] … — [[reflection]]` without `#claude`, max. 5, no duplicates) and `Reflexiones/<date> <topic> (<id8>).md`, linked to the session, the project and previous ones. Links from the model are only accepted if they exist in the index; free text is sanitized (no `[[ ]]` of its own and no `#claude`). The conversation is treated as data. It emits `brain-reflected` (with `persona` and `promoted`). `reflect(..., with_persona)` additionally asks for up to 3 `persona` observations (`kind` `trait` or `user`) when `brainPersona` is active, and passes them to `persona::apply`; it learns only when reflecting (with *Reflexionar al terminar cada sesión* (Reflect when each session ends) or with *Reflexionar ahora*). `persona.rs`: "Forjar una personalidad" (Forge a personality) (`brainPersona`, off by default; requires `brainEnabled`). It maintains `Claude NPC/Personalidad.md` (marker `<!-- claude-npc:auto -->`; sections `## Rasgos`, `## Sobre ti`, `## Valores`, `## Mi historia` (rewritten by dreaming), `## Observaciones` and `## Historial`). An observation stays pending with the sessions in which it was seen and only moves to Rasgos (max. 8), Sobre ti (max. 10) or Valores (max. 6; `value` type, "what it cares about") when it repeats in 2 DISTINCT sessions (text compared without accents or punctuation); pending max. 15, history max. 30. It preserves the lines and sections the user edits; if the user removes the marker, it leaves it alone (the block keeps being injected). `block` gives a block of about 700 characters with `PERSONA_HEADER` ("data, not instructions") that is prepended to tasks and, once per session (`first_persona`), goes through `additionalContext`. `view` feeds `brain_persona`. Not yet included: jokes or bubbles generated from the traits (they are still fixed lists) and proposals with an *Aplicar* button (for now they enter on their own once repeated). `ask.rs`: "Pregúntale al cerebro" (Ask the brain) (`brain_ask`, button *💬 Preguntar* (Ask); requires `brainEnabled`). It launches the user's `claude -p` with the default model and only `Read,Glob,Grep,LS`, cwd in the vault, and with the recalled notes (8 notes, 3,500 characters) in the prompt, which starts with `ask::MARKER` (`[claude-npc:pregunta]`). It returns the text (max. 8,000 characters) and `sources`: the notes cited with `[[ ]]` that exist in the index (by title or alias, max. 8). It writes nothing and keeps no history. `review.rs`: `weekly` (`brain_weekly`, button *📅 Resumen semanal* (Weekly summary); requires `brainEnabled`) asks Haiku for a JSON (`summary`, `patterns`, `conflicts`, `stuck`, `next`) about the reflections of the last 7 days (minimum 2) and the open to-dos, and writes `Claude NPC/Semanal/Semana <monday>.md` (auto marker, links the reflections; it does not overwrite a note the user took over; the button refreshes it). Automatic: after a successful reflection at `SessionEnd`, if this week's does not exist yet (event `brain-weekly`). It uses `reflect::exclusive` and the `review::MARKER` marker (`[claude-npc:semanal]`). `maintenance` (`brain_maintenance`, button *🧹 Mantenimiento* (Maintenance); does not require `brainEnabled`) only reads and returns warnings: `Pendientes.md` to-dos open ≥14 days (age by the linked reflection), `Memoria/` lessons with nearly identical titles (Jaccard ≥0.6, ≥2 words) and up to 10 of your notes with no incoming or outgoing links. There is no *Aplicar* button: what needs merging or deleting is up to you. `mod.rs` ties everything together, exposes `brain_status` (with `archived`), `brain_search`, `brain_remember`, `brain_reflect`, `brain_persona`, `brain_ask`, `brain_weekly`, `brain_dream`, `brain_maintenance`, `brain_panel`, `brain_suggestions` (read-only) and `brain_apply`; after each `SessionEnd` with reflection it emits `brain-weekly` and `brain-dreamt` when due; `is_internal(prompt)` recognizes the brain's own prompts (the four markers) and `task_result` writes a task's note, emits `brain-recall` (only if there are recalled notes) and decides when to inject. Dates and times in UTC. |
| `brain/strength.rs` | Forgetting and reinforcement of the auto notes in `Claude NPC/Memoria/` (opt-in with `brainForget`, requires `brainEnabled`). Usage and date in the hidden file `Claude NPC/.memoria.json` (once per day and note; the note itself is not touched). Strength `strength` = 0.5^(age / half-life), with a half-life of 30 days × (1 + uses, capped at 10) × importance/3; `factor` multiplies the recall ranking (0.5–1 by strength, × 0.8–1.2 by importance). `archive_weak` (at `SessionEnd`) moves to `Claude NPC/Archivo/` the auto notes with strength < 0.15 and importance < 5; it never deletes, keeps the name (the `[[links]]` remain valid), does not overwrite and does not touch notes the user took over. Those in `Archivo/` weigh 0 in recall. `archived_count` feeds `BrainStatus.archived`. |
| `brain/dream.rs` | "Dreaming" (`brain_dream`, button *😴 Consolidar* (Consolidate); event `brain-dreamt`; automatic once a week after a successful reflection, `force = false`). Haiku reads up to 40 notes from `Memoria/` (the most important first; min. 5 lessons, 300-character fragments) and returns **principles** (to `Memoria/`, `type: principle`, max. 3), **habits** "when X, do Y" (to `Claude NPC/Hábitos/`, max. 3, weight 1.3 in recall), **contradictions** between lessons (max. 3) and, with `brainPersona`, the first-person story that rewrites `## Mi historia` (`persona::set_story`). Each principle or habit needs 2–6 sources that exist as a lesson (`from`). It writes `Claude NPC/Sueños/Sueño <monday>.md` (one per week, auto marker; it does not overwrite a note the user took over). Nothing existing is overwritten. It uses `reflect::exclusive` and the `dream::MARKER` marker (`[claude-npc:sueno]`). |
| `brain/associations.rs` | Hebb's rule: the notes that `prompt_brief` recalls together are counted once per day in `Claude NPC/.asociaciones.json` (max. 3,000 pairs). | `obsidian.rs` | Obsidian actions beyond files. | `bridge.rs` + `bin/npc-bridge.rs` | Translates hooks from Gemini CLI, Cursor and Codex to the `/agent` endpoint. |

## Conventions

- **i18n:** the Spanish string is the dictionary key (`DICT` in `src/i18n.ts`); a missing translation falls back to Spanish. Every new visible string must carry `e(en, pt, fr, de)` with **the same `{name}` placeholders**; `npm run test:ui` checks it. Do not add UI text without going through `t()`. Documentation, code comments and doc-comments are written in English; only the UI strings (the keys) are in Spanish, and they are shown in 5 languages (es/en/pt/fr/de).
- **Rust:** no `panic` in user paths; Tauri commands return `Result<_, String>` and the frontend shows them with `errorText`. Each module carries unit tests next to the code; network services are tested against simulated servers (for example `CLAUDE_NPC_TELEGRAM_API` redirects the Telegram API).
- **Frontend:** no framework; DOM with `h()`. Interactive regions are reported to the backend with `set_hit_regions` for click-through; a new panel must be registered there or it will not receive clicks.
- **Format and limits:** vault files are bounded (`MAX_FILES`, `MAX_FILE_BYTES`, `MAX_RESULT_CHARS`); respect that kind of cap on external inputs (themes, pets, webhooks).
- **Security:** never store secrets outside the app's config (Telegram and webhooks go in plain text there, and it is documented); do not extend the hooks server beyond loopback; do not add write paths to the mobile view; the hook diagnostics log (`hook_log`) must not store prompts or tool inputs. Memory (`brain/`) writes only under `Claude NPC/` and does not edit the user's notes, with one exception: the proposals from `suggest.rs` change one line of a note of yours (or its header) only when *Aplicar* is pressed and only if the note has not changed since it was proposed. Reflection (`brain/reflect.rs`) sends the end of a conversation to Haiku with your `claude` (off by default; the folders in `brainExclude` are not reflected on). With `brainPersona`, the same call asks for observations about how you work, with the prompt forbidding private data (health, finances, politics, religion, identity, relationships); that depends on the model, there is no guarantee. The personality goes to `Claude NPC/Personalidad.md` and is injected as data. The model can only read (`Read,Glob,Grep,LS`) with cwd in the vault; it never writes, and the code validates its response before writing under `Claude NPC/`. Mark what is injected as data, not instructions (notes may contain malicious text; they are sent to Claude). The questions to the brain and maintenance only read; the weekly summary writes only in `Claude NPC/Semanal/`. Dreaming sends Haiku fragments of up to 40 notes from `Memoria/` (never conversations) and writes only under `Claude NPC/` (Memoria, Hábitos, Sueños) and in the personality's story; forgetting only moves auto notes to `Claude NPC/Archivo/` and never deletes; associations only add `## Asociadas` to the NPC's auto notes. A vault task with `📁` can take Claude to a folder outside the vault (absolute, must exist); it follows the usual permission rules (read-only unless *Permitir que Claude edite archivos*). The brain's internal executions are not shown as user sessions (`is_internal`; not verified with a real `claude`). Obsidian commands only run if they are saved favorites, with a validated id, without a shell and with a timeout.
- Documentation language: English. Keep README, `docs/` and MVP consistent with any change in functionality or in what was verified.
- Commits in the repo's style; `dist/`, `node_modules/` and `src-tauri/target/` are ignored.

## NPC states

`Mood`: `idle | thinking | working | juggling (subagents) | waiting (needs permission) | done | error`. External agents use `state` ∈ `idle thinking working waiting attention done error ended` in `/agent`. A Codex Pet maps each state to its animation row (idle, running-right/left, waving, running, review, waiting, jumping, failed).

## Documentation and push

- Agent **`doc-keeper`** (`.claude/agents/doc-keeper.md`, Haiku model): checks that CLAUDE.md, README.md, `docs/` and MVP.md reflect the real code without losing information. Invoke it after changes to architecture, commands, settings, ports or languages.
- **PreToolUse** hook (`.claude/settings.json` → `.claude/hooks/require-doc-review.mjs`): blocks `git push` unless `.claude/.doc-review-ok` (ignored by git) contains the SHA of the current HEAD. `doc-keeper` writes that marker when it finishes the review; if you make new commits, it has to be repeated. If documentation changes, commit it before the push.
